# Bloodborne for Apple Silicon 0.6.0

This release introduces the independent Bloodborne launcher with profiles, save management
and GitHub release notifications, plus opening-video and renderer fixes.

## Launcher

- First-profile setup adopts existing saves on upgrade. Additional profiles start with new
  saves. Create, rename, select or delete profiles; deletion requires confirmation and removes
  that profile's saves and backups.
- Back up and restore save sets from the Saves tab. Profile ownership and recovery use SQLite
  with transactional migrations; shader caches are shared between profiles.
- The active profile is visible on Home. Trophy collection and save editing are marked as
  in development; they are not available in this release.
- The launcher can hide to the menu bar while playing and return when the game exits. Turn
  this off in Advanced to follow logs. The tray menu can show the launcher or stop the game.
- Stable app releases are checked automatically, with a changelog modal and GitHub release
  link. Advanced includes manual checks and an automatic-check preference. Installation is manual.
- Settings are grouped by Graphics, Game, Profiles, Saves and Advanced. The launcher supports
  all 20 game languages.

## Runtime

- Shared movie/render state is guarded across updates and draws, addressing the captured
  opening-video null-read race.
- Video queue access and frame ownership are synchronized. Audio/video clock state is locked
  and uses steady time.
- Condition-variable retirement handles the movie-thread destroy/signaling race; NV12 frame
  invalidation covers the padded copy size. Credit: Bloodborne-Android `bf1e6cf`.
- The portable SRT interpreter is the arm64 default, removing translated SRT code from the
  renderer. `BB_SRT_INTERP=0` remains the fallback. Credit: ARM_bloodborne_pc `3d56243` and
  Bloodborne-Android `bf1e6cf` for its 0.51 adaptation and cache handling.
- Deferred clears are enabled by default, folding eligible clears into attachment load actions.
  `BB_DEFER_CLEARS=0` remains the off switch. Experimental renderer migration stays opt-in.

## Verification and known issues

Seven accepted pre-release opening-video trials completed and were observed as successful,
including two self-contained downloaded-package runs and one empty project-cache check.
Packaged copied-save gameplay passed a 90-second hold on an M3 Pro: 47.3 FPS and 22.9 ms p90
at 1920×1080 output / 1130×636 scene. These are short acceptance checks, not a guarantee that
rare faults are eliminated. See [stability results](https://github.com/bloodborne-native/bloodborne-runtime/blob/main/docs/STABILITY.md).

- Offline play on macOS. Online integration is not included.
- Black sky and object popping in some Yharnam areas remain under investigation.
- Rare sampler/GPU assertions and movie shutdown faults seen in earlier development runs
  remain on the watch list; none appeared in this acceptance batch.
- Packaged first-profile setup and Home were verified with synthetic data on this Mac.
  Full clean-machine/Gatekeeper behavior has not been verified on another Mac.

## Install or update

Download the Apple Silicon DMG and replace Bloodborne.app. Saves/settings remain in
`~/Library/Application Support/bloodborne_mac`. No game files are included: supply your own
Bloodborne dump with update 1.09. The app includes its runtime, bash, Python and libraries.

The app is signed ad hoc, without an Apple Developer ID. On first launch use macOS's Open / 
Privacy & Security approval flow as described in [Installation](https://github.com/bloodborne-native/bloodborne-mac/blob/main/docs/guide/installation.md).

Based on bbport and shadPS4; additional contributors and licenses are listed in
[Credits](https://github.com/bloodborne-native/bloodborne-runtime/blob/main/docs/CREDITS.md).
Our app version follows this project's releases independently of upstream bbport versions.
